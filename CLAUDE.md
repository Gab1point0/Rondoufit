# Rondoufit — contexte du projet (à lire en premier)

Application de fitness façon RPG Pokémon pour **un seul utilisateur** (français, Gabin). Publiée sur GitHub Pages depuis `main` (repo `gab1point0/rondoufit`) : https://gab1point0.github.io/Rondoufit/

## Règles de travail avec l'utilisateur
- Parler **français**, réponses courtes, orientées résultat. L'utilisateur n'est pas développeur : instructions simples, pas de jargon.
- **Pousser sur `main` automatiquement** une fois les tests faits (autorisation permanente de l'utilisateur, 21/10/2026), puis **expliquer clairement ce qui a changé**. Ne pas publier de données personnelles. Pour un gros chantier (refonte, changement de sauvegarde…), demander avant de publier.
- Commits : message en français + trailers `Co-Authored-By` / `Claude-Session` demandés par l'environnement.
- Les évolutions sont des demandes de fonctionnalités ; lancer `npm test`, puis vérifier dans un navigateur (`npm run dev`) avant de livrer.

## Pile et commandes
Vite 8 · React 18 · Tailwind 3 (compilé, plus de CDN) · JavaScript/JSX (pas de TypeScript) · Vitest + jsdom pour les tests.
```
npm run dev      # serveur local http://localhost:5173
npm test         # tests : fusion/synchro (logique) + parcours complets de l'appli (faux navigateur)
npm run build    # dist/ (c'est ce que GitHub Actions publie)
npm run icons    # régénère public/icon-*.png depuis assets/icon-source.png
```
Déploiement : push sur `main` → `.github/workflows/deploy.yml` (tests + build + Pages). `vite.config.js` utilise `base: './'`. Application installable et utilisable hors ligne (`public/sw.js`, `public/manifest.webmanifest`).

Accueil : la grande carte **Coach** (`components/CoachBanner.jsx` : prochaine séance, « Lancer ma séance », « Ouvrir le Coach ») est en haut de la page, sous un en-tête compact (`header/HeaderProfile.jsx` : avatar, jauge d'EXP, pastilles, bouton ⚙️). Les actions de saisie rapide sont dans le bouton « + » flottant (`components/QuickAddMenu.jsx` : course / marche, nouvel exercice, dictée, minuteur) ; les données et réglages (sons, texte plus grand, sauvegarde GitHub, exporter, importer, copie de sécurité, réinitialiser) et les pages secondaires dans le menu « Plus » / ⚙️ (`modals/MoreSheet.jsx`). La dictée vocale (`VoiceWorkoutAssistant`) n'a plus de bouton : elle s'ouvre par l'événement `rondoufit-voice`.

Navigation (`components/TabBar.jsx`, liste `TABS`) : ordinateur / tablette = barre d'onglets en haut (`TabBar`) ; téléphone = barre fixe en bas (`BottomNav` : Coach, Exercices, Journal, Suivi, Plus) + pastilles de sous-onglets (`SubTabs` : Courbes / Maxima / Poids, ou Souvenirs / Bilan / Trophées). `goToTab(tab)` (App.jsx) ouvre un onglet puis fait défiler jusqu'au début du contenu (`tabsRef`, `scrollIntoView` après 60 ms). La page Coach garde ses réglages repliés dans `components/coach/Fold.jsx` ; dans « Prochaine séance » l'explication et « Tu décides » de chaque exercice sont repliés (bouton « Pourquoi ? / Ajuster »). Le minuteur de repos (`RestTimer`) n'est visible que s'il tourne, est ouvert, ou pendant une séance guidée ; il affiche le rappel de la série suivante (événement `rondoufit-rest` avec `{ sec, next }`). Photos : `PhotoAddButton` reçoit `capture="environment"` (appareil photo arrière) ou `"user"` (selfie) pour ouvrir directement l'appareil photo du téléphone ; sans `capture` il ouvre la galerie (plusieurs photos possibles).

Robustesse et confort : `components/ErrorBoundary.jsx` (écran « Oups » avec Recharger / Exporter si un écran plante), `lib/updateCheck.js` + `components/UpdateBanner.jsx` (bandeau « Nouvelle version disponible » : on compare le nom du fichier JS haché de la page d'accueil), `lib/safetyCopy.js` (copie automatique avant import / réinitialisation, restaurable depuis « Plus », clé `rondoufit:safetyCopy`), `lib/uiPrefs.js` (« Texte : grand » = taille de base 18 px, clé `rondoufit:ui` ; les textes sont en rem pour suivre). Enregistrement d'une séance de musculation : un seul module, `lib/sessionRecord.js` (`applyStrengthSession`), utilisé par « Noter séance » et la séance guidée ; « Noter séance » a le bouton « Remplir comme prévu par le coach ». App.jsx donne à chaque fenêtre l'objet complet de son hook (`<LogSessionModal {...log} />`) : un nouveau champ renvoyé par le hook arrive tout seul dans la fenêtre.

Pour modifier un écran : le fichier de `tabs/`, `modals/` ou `components/` correspondant. Pour une règle du coach : `coach/`. Pour ajouter un exercice : `data/catalog.js` (+ alias vocaux dans `voice/dictionary.js`).

## Modèle de données
État principal `gameState` : `xp, quests, weightHistory, unlockedAchievements, claimedChallenges, userWeightKg, targetWeightKg, coach, …`. Fusionné avec `INITIAL_STATE` (`data/initialState.js`) au chargement (`normalizeState`) : **tout nouveau champ doit avoir une valeur par défaut dans `INITIAL_STATE`**.
`claimedChallenges` : champ gardé pour les anciennes sauvegardes (les « Défis de la semaine » de l'onglet Bilan ont été supprimés en 10/2026 ; les « Objectifs de la semaine » du Coach les remplacent).

Quête : `{id, catalogId, name, category, type:'strength'|'cardio', unit:'kg'|'reps'|'min'|'km', goalMode, goalSets, goalReps, startValue, currentValue, goalValue, setDetails, history[], timed?}`. Entrées « Point de départ » reconnues par `isStartEntry`. Chaque quête et chaque entrée d'historique / pesée a un `id` unique (la fusion de la sauvegarde s'appuie dessus).

Exercices chronométrés (planche…) : `timed:true`, valeurs en secondes (`isTimedQuest`, `repUnit`, `timedAdvice`, `TIMED_PRESETS`), +5 s par progression. Salle de l'utilisateur : abdos obliques/transverses uniquement via *Hammer Strength Oblique Crunch* (`hs_oblique_crunch`) et *Technogym Total Abdominal* (`tg_total_abdominal`).

Coach (`coach/`, repères : ACSM 2009, Schoenfeld 2016/2017, Spiering 2021, Garthe 2011, Morton 2018, Bell 2023, Mifflin 1990, Epley 1985) : progression auto (`computeExerciseTarget`), planning hebdo avec volley jeudi/vendredi, matchs, créneaux de salle, mode 3 séances, durée cible 60 min, séance guidée, bilan, nutrition, objectifs hebdo. Ce n'est pas un avis médical.

- **Habillage neutre** : rangs et trophées renommés (`data/gamification.js`, mêmes ids et mêmes bonus), thèmes sobres sans accessoires (`data/rewards.js`, thème « ardoise »), avatar initiale (`components/NeutralAvatar.jsx`), titre « Ma musculation », couleurs : les classes Tailwind `pink / fuchsia / purple / violet / indigo` passent par des variables CSS (`src/palette.css`, GÉNÉRÉ par `node tools/make-palette.mjs`, lu par `tailwind.config.js`) → rose en fun, bleu / ardoise en neutre ; icônes et manifeste neutres dans `public/neutral/` (générés par `node tools/make-neutral-icons.mjs`, échangés au démarrage par `applyEdition()` pour que l'appli installée s'appelle « Ma musculation »).
- **Assistant d'accueil** (`modals/OnboardingModal.jsx`, logique pure testée `lib/onboarding.js` : `applyOnboarding`) : s'ouvre tout seul sur une appli neuve de l'édition neutre (`needsOnboarding`) ou via ⚙️ → Assistant d'accueil. 8 écrans : prénom, profil (sexe, âge, taille, poids, poids visé), objectif (→ `coach.workProfile`), organisation (séances / semaine, durée, jours → `gymSlots`), exercices connus + charges (→ quêtes + `maxRecords`, départ calculé d'après le profil), sport régulier (→ `coach.volleyDays`, mot « sport »), sauvegarde GitHub guidée, récapitulatif. `gameState.onboarded`. Dans l'édition neutre `volleyDays` vaut `[]` par défaut et le dépôt par défaut est `muscu-donnees` (pas ton compte).
- **Sauvegarde des amis = exactement la tienne** (GitHub privé, automatique, fusion à 3 voies, clé gardée sur l'appareil) ; l'assistant guide la création du compte, du dépôt privé et de la clé fine-grained (liens préremplis).

## Niveaux, EXP, rangs (refonte du 21/10/2026)
- **Courbe** (`lib/levels.js`) : EXP cumulée pour le niveau L = 300 × (L−1)^1,6 (niveau 5 ≈ 2 800 EXP, 10 ≈ 10 000, 20 ≈ 33 000, 50 ≈ 150 000). Pour changer le rythme, ne toucher qu'à `XP_BASE` / `XP_EXPONENT`. Niveau max 100.
- **Rangs** (`data/gamification.js`, `RPG_RANKS`) : 7 rangs, du niveau 1 (Novice) au 50 (Maître des Arènes).
- **Épreuves de rang** (`data/trials.js`, `hooks/useRankTrial.js`, `modals/RankTrialModal.jsx`) : pour passer un rang il faut aussi réussir une épreuve (jours d'entraînement, semaines d'affilée, exercices niveau 2+, kcal). Tant qu'elle n'est pas réussie, le niveau reste bloqué juste avant le rang (`levelInfo.locked`) et l'EXP s'accumule en réserve. Réussies : `gameState.rankTrials` (niveaux des rangs).
- **EXP gagnée** : toujours via `computeXp(state, base, today, kind)` de `lib/xp.js` (jamais `xp: prev.xp + n`), avec `kind` = `'session'` (bonus de régularité +10 %/semaine d'affilée, max +50 %, puis plafond du jour), `'minor'` (plafond seulement) ou `'reward'` (trophées, défis, objectifs hebdo : tel quel). Plafond du jour : au-delà de 600 EXP gagnées dans la journée l'EXP de séance compte moitié. `computeXp` renvoie aussi le `patch` à fusionner dans l'état (`xp`, `xpWeeks` = EXP par semaine pour le Bilan, `xpDaily`).
- **Récompenses** (`data/rewards.js`, `modals/RewardsModal.jsx`) : thèmes de couleur, accessoires de Rondoudou et titres débloqués par niveau (`gameState.cosmetics`) ; le cadre de l'avatar change avec le rang.
- **Célébrations** (`hooks/useLevelCelebration.js`, `modals/RankUpModal.jsx`) : message à chaque niveau, grande fenêtre à chaque nouveau rang. **Bilan** : `components/XpProgress.jsx` (courbe d'EXP, dates estimées).
- Trophées : bonus d'EXP divisés par deux par rapport à l'ancienne version. La fusion de synchro additionne les gains `xp` / `xpWeeks` des deux appareils et réunit `rankTrials`.

## Ressenti par exercice (RPE 1 à 10)
Séance guidée (`components/GuidedSession.jsx`) : chaque exercice a sa note de ressenti (`g.data[questId].rpe`, 1 à 10, avec la signification en répétitions en réserve) ; `handleFinishGuided` l'enregistre dans `entry.rpe` (à défaut : ressenti global de la séance `g.rpe`). « Noter séance » avait déjà un RPE par exercice. Le coach (`coach/targets.js`, `computeExerciseTarget`) lit `rpe` de la dernière séance de l'exercice : ressenti ≤ 6 et objectif atteint → augmentation plus forte (charge +2,5 pts de %, ou aide −2,5 kg de plus) ; ≥ 9 sans gros dépassement → on consolide ; un recul (2 séances sous l'objectif à la même charge/aide) n'a lieu que si le ressenti de la dernière séance était ≥ 8.

## Profils de travail du coach (puissance / hypertrophie / endurance de force)
`coach/profiles.js` (`PROFILES` : fourchette de reps, séries, % de départ du max, repos ; `pctForReps` ; `coachProfileAt(coach, iso)` ; `profileOpts(state, iso)`) et `coach/profileTarget.js` (`decideProfileTarget`). Réglages : `coach.workProfile` (`'auto'` = ancien calcul, ou `puissance` | `hypertrophie` | `endurance`) et `coach.cycleProfiles` (liste de profils, un par cycle, qui se répète ; utilisée seulement si les cycles sont activés). ⚠️ `coach.profile` est le profil CORPOREL (taille, âge, sexe), à ne pas confondre. `computeExerciseTarget(q, { profile, maxRecords, … })` : avec un profil, il fixe séries, répétitions, repos et charge (hors exercices chronométrés) ; tous les appelants passent `...profileOpts(state, date)`. Progression à double échelon : +1 rép par série jusqu'en haut de la fourchette, puis charge supérieure (3,5 %, 5 % si ressenti ≤ 6) en repartant du bas ; si la dernière séance sort de la fourchette (changement de profil), la charge est recalculée d'après le max estimé (`lib/maxima.js`) ou le record réel (`maxRecords`), avec un plafond de +15 % / −20 % d'un coup (`change: 'profile'`). Repères : ACSM 2009 / NSCA (continuum des répétitions) nuancés par Schoenfeld 2021 et Lopez 2021 ; UI : `components/coach/CoachProfile.jsx`, pastille dans `CoachNextSession.jsx`.

## Départ d'un nouvel exercice (maxima + profil)
`coach/startSuggestion.js` : `suggestStart(catalogExercise, state, today, catalog)` → `{startValue, goalValue, goalSets, goalReps, profile, note}`. Niveau relatif de force (`relativeStrength`) = moyenne géométrique (exercices de la même arène comptés ×3) de « ton max estimé ou record réel / max d'un débutant sur cet exercice » (déduit de la charge de départ du catalogue), borné à 0,5–2,5. Automatique : charge du catalogue × niveau ; avec un profil : max estimé × % de départ du profil ; séries et reps visées = celles du profil. Cardio, chronométrés et exercices en reps : pas de charge inventée. Utilisé par le formulaire « + Objectif / Exercice » (`useQuestForm`, encart 💡 dans `QuestFormModal`), l'ajout par le coach (`addQuestFromCatalog`) et la dictée vocale (séries/reps du profil, charge dictée). Tests : `src/coach/startSuggestion.test.js`, `tests/ui/depart.test.js`.

## Échauffement dans la séance guidée
`coach/warmup.js` : `warmupSets(item, exercicesPrécédents, chargeActuelle, aideActuelle)` → 1 ou 2 séries (pas plus). Calculé à l'affichage (`GuidedSession.jsx`, bloc `data-testid="warmup"`) d'après la charge de travail du moment : premier exercice d'une arène avec charge significative → 50 % × 8 puis 70 % × 5 (80 % × 3 si travail ≤ 6 reps ou profil Puissance) ; arène déjà échauffée ou accessoire → 1 série à 60 % × 6 ; charge < 15 kg → 50 % × 10 ; aide élastique → +10 kg d'aide, moitié des reps ; poids du corps / chronométré → moitié du travail. Cochée dans `data[questId].wdone` (lance un repos de 30-60 s) ; **jamais enregistrée** dans l'historique, l'EXP, les calories ni le coach. Remplace l'ancien encart d'échauffement global (`g.warmup` reste dans la séance mais n'est plus affiché ici ; il est encore montré dans « Prochaine séance »). Tests : `src/coach/warmup.test.js`, `tests/ui/echauffement.test.js`.

## Calculs de calories (`lib/calories.js`, testés dans `calories.test.js`)
Toutes les calories sont **nettes** (repos retiré : 1 MET = 1 kcal/kg/h), donc elles s'ajoutent au métabolisme de base de `coachNutrition` (Mifflin-St Jeor × 1,2) sans double compte. Course, marche, randonnée, trail, marche nordique (+20 %) : équations ACSM (vitesse + pente), transition marche → course entre 6 et 8 km/h. Vélo (route, VTT +1,5 MET, ville, électrique ×0,6), natation, kayak, aviron extérieur, paddle, roller, ski de fond, raquettes, trottinette : MET du Compendium 2011 **selon la vitesse** (tables dans `SPEED_MET`), plus la montée (énergie potentielle ÷ 25 %, moitié pour l'électrique) pour `OUTDOOR_CLIMB_MODES`. Rameur et ski-erg : puissance P = 2,8 v³ ÷ 23 %. Autres activités (sports collectifs, raquette, cours) : MET × `rpeFactor` (1 à RPE 6, ±7 % par point, jamais négatif). Musculation : MET moyen 3,5 → 6,5 selon ressenti et charge relative × durée estimée (2,2 min par série + 3 s par répétition). Plancher 5 kcal seulement.

## Activités annexes (« + Activité annexe »)`data/activities.js` : ~85 activités (sports collectifs, sports de raquette, plein air, eau et glisse, cardio en salle / cours) avec leur MET brut (Compendium 2011) ; `data/catalog.js` en fait des exercices `type: 'cardio'` avec un `group`. Calories : voir « Calculs de calories » ci-dessous. **Le dénivelé et la pente n’existent que pour la course, la marche, la randonnée, le trail et le vélo en extérieur (route, VTT, ville, électrique)** (`cardioHasElevation(mode)`, modes `run`, `interval`, `walk`, `incline_walk`, `hike`, `trail`, `nordic`) : masqués ailleurs (fenêtre, Noter séance, Journal, correction) et ignorés dans le calcul. Distance seulement si l'unité est le km (natation, vélo, kayak, roller, ski de fond…) ; sinon la durée seule. Ajouter une activité : une ligne dans `ROWS` (le test `activities.test.js` vérifie la cohérence).
## Cardio : vitesse + durée, pente en %
`lib/calories.js` : `resolveCardioInputs({ inputMode: 'distance'|'speed', slopeMode: 'meters'|'percent', … })` transforme « 10 km/h pendant 5 min » en distance (vitesse × durée) et « pente 10 % » en dénivelé positif (pente × distance) ; tout le reste (calories ACSM, historique, courbes) continue de ne lire que `distanceKm` / `durationMin` / `elevationM`. `cardioInputNote` ajoute « à 4 km/h, pente 10 % » aux notes automatiques. UI : `components/CardioInputToggles.jsx`, utilisé par « + Course / Marche » (`useQuickCardio`, `QuickCardioModal`) et par « Noter séance » d'un exercice cardio (`useLogSession` : `logCardioInput`, `cardioFigures`). Tests : `src/lib/cardioInput.test.js`, `tests/ui/cardio-vitesse.test.js`.

## Voir le mouvement (animations de tous les exercices de musculation)
Bouton « 🎬 Mouvement » sur les cartes d'exercice, dans la séance guidée, « Noter séance » et la prochaine séance du Coach : `lib/movement.js` (`openMovement`) lance l'événement `rondoufit-movement` ; `components/MovementPreview.jsx` (monté dans App.jsx) affiche l'animation (lecture / pause / lent / barre de position), le trajet moteur en pointillés jaunes (cercle = départ, flèche = sens de l'effort) et les conseils (muscles, installation / machine, geste, respiration, erreurs).
- **Moteur** (`src/anim/`) : `skeleton.js` = bonhomme de profil (cinématique inverse à 2 segments : une pose donne hanche, angle du buste, cible des mains / des pieds ; coudes et genoux sont calculés ; `poseAt`, `tracePath`) et vue de FACE (`view: 'front'`, `solveFront` : élévations latérales, oiseau, adducteurs…) ; `Figure.jsx` = dessin SVG ; `kit.js` = décor (bancs, sièges, plaques, poulies…) et charges liées au corps (disque, haltère, câble, levier…).
- **Scènes** : `scenes-push.js`, `scenes-pull.js`, `scenes-shoulders.js`, `scenes-arms.js`, `scenes-legs.js`, `scenes-core.js` = une fonction par famille de mouvement, paramétrée par le matériel (barre, haltères, Smith, machine, poulie). `registry.js` associe chaque identifiant du catalogue à sa scène. Une scène = `{ keys:[poses], trace, loop:'pingpong'|'cycle', equip:[décor], follow:[charges], hold? }`.
- **Textes** : `info.js` (`FAMILIES` : muscles / installation / geste / erreurs, `INFO_FAMILY` : exercice → famille, `EQUIP_TIPS` : conseils selon le matériel, `NAME_RULES` : reconnaissance d'un exercice personnalisé d'après son nom) ; `resolve.js` relie tout.
- **Catalogue des machines de marque** : une seule entrée par mouvement, nommée de façon générique (« Chest Press Machine », « Rotary Torso »…) ; le champ `brands` (ajouté en fin de `catalog.js`, par type de machine) liste les marques pour la recherche (Technogym, Matrix, Life Fitness, Hammer Strength, Gym80, BH, Bodytone). Une machine propre à une marque dont la mécanique diffère a sa propre entrée (Hammer Strength Oblique Crunch, Technogym Total Abdominal). Salles visées : Basic-Fit (Matrix + Technogym), Fitness Park (Technogym, Hammer Strength, Gym80), L'Orange Bleue (BH + Bodytone) d'après leurs sites ; les catalogues complets des fabricants n'étant pas accessibles, la liste est établie par mouvement.
- **Plusieurs angles de vue** : par défaut l'animation est de profil. Quand le profil masque le mouvement (bras tendus, écartés, tractions, tirages, rowings, développés épaules, squats, pompes, dips…), `scenes-alt.js` ajoute une vue de face / de dos / depuis les pieds / depuis la tête, attachée à l'exercice par `alt(ids, clé, libellé, scène)` dans `registry.js` ; la fenêtre affiche alors le sélecteur « Angle de vue ». La vue de face (`view: 'front'`) accepte : mains / pieds symétriques (`hand`, `foot`, `knee`), un côté gauche indépendant (`handL`, `footL`, `kneeL`), des bras par angles (`arm`), buste penché (`bend`), `noLegs`, `noHead`, `back` (vue de dos), `box` (zoom) et la barre horizontale `hbar`. **Étiquettes de phase** : `p[0]` de la famille (info.js) décrit le trajet clé 0 → clé 1 de la scène, `p[1]` le retour : si tu changes l'ordre des clés d'une scène, échange les deux étiquettes.
- **Machines précises** : une machine de marque a sa propre scène quand sa mécanique diffère (ex. `hsObliqueCrunch` = Hammer Strength à plaques en DOUBLE ACTION (le buste s'enroule ET les genoux montent grâce au coussin de jambes, d'après la machine « seated leg raise oblique crunch » ; détail du coussin à confirmer par l'utilisateur), siège pivotant G / centre / D, poignées par-dessus les épaules ; `tgTotalAbdominal` = Technogym Selection 900, appui des jambes + coussin postérieur de hanche + pile). Les machines Hammer Strength sont dessinées avec des plaques sur cornes (`horn` dans `kit.js`), les machines à pile avec un bloc de plaques. Sources et limites : descriptions des fabricants (Life Fitness, Technogym) ; pas de manuel détaillé trouvé → l'utilisateur corrige d'après sa machine.
- **Ajouter un exercice au catalogue** : ajouter sa scène dans `registry.js` (`add(id, nom, scène)`) ET sa famille dans `INFO_FAMILY` (le test `src/anim/anim.test.js` échoue sinon).
- **Précision (validateur)** : `anim.test.js` vérifie que chaque `hand` / `foot` de chaque scène et de chaque angle de vue est atteignable (≤ 6 px) ; `handRel: [dx, dy]` place la main par rapport à l'épaule (bras pendants : soulevés de terre) ; `plank(ankle, shoulder)` + `shoulderXFor(ankle, y)` (scenes-pull) construisent un corps gainé par cinématique inverse (pompes, rowing inversé, burpees, planche) ; `lerpPose` convertit tout seul les angles (`arm` / `leg`) en cible quand l'autre clé utilise une cible, et prend le chemin le plus court pour les angles.
- **Personnage et muscles** : `Figure.jsx` dessine des membres effilés (`Taper`), une tête avec cheveux et œil, une ombre au sol ; `muscles.js` (`musclesOf(info.m)`) transforme le texte « Muscles travaillés » en zones (pectoraux, épaules, bras, dos, abdos, fessiers, cuisses, mollets…) qui battent en rouge sur le bonhomme (le premier muscle cité est le plus marqué) : prop `muscleText` de `<Figure>`.
- **Rythme, respiration, fantôme, erreur fréquente** (`MovementPreview.jsx`) : `tempoU` / `TEMPO` (skeleton.js) = montée 36 % du cycle, pause, retour contrôlé 50 %, pause ; pastille Respiration (Expire / Inspire) et compteur « Rép. n » ; un « fantôme » pâle (`<Figure ghost />`, calque par-dessus) montre la position visée ; surbrillance de l'étape du texte « Le mouvement » ; sélecteur « Erreur fréquente » (vues de profil, hors tenues) : trop vite avec élan, amplitude trop courte (fantôme = trajet complet), dos qui lâche — le bonhomme passe en rouge (`bad`).
- **Vue de dessus** (`view: 'top'`, `solveTop` / `traceTop` dans skeleton.js, `TopFigure` dans Figure.jsx) : bassin fixe, épaules qui tournent (`twist`), `hand` / `handL` absolus, `legs: 'seated' | 'standing'` ; utilisée pour rotary torso, bûcheron et Pallof press. Autres vues ajoutées au lot 4 : soulevés de terre (conventionnel / sumo), curls (alternés pour les haltères), shrugs, vus de face.
- **Chargement à la demande** : App.jsx monte `components/MovementHost.jsx` (`React.lazy` de `MovementPreview`, préchargé au repos du navigateur ; le premier événement d'ouverture est transmis par la prop `initial`). La séance guidée affiche une mini-animation (`components/MiniMovement.jsx`, lazy, masquable : clé `rondoufit:miniAnim`) ; avec « réduire les animations » (prefers-reduced-motion) l'animation est remplacée par 3 images (départ / milieu / fin). Bouton « 🚩 Cette animation est fausse » → `flagAnimation` (lib/movement.js) → App.jsx ajoute `{ id, animId, view, name, at }` à `gameState.animFlags` (synchronisé et fusionné par id) : pour corriger, lire `animFlags` dans `rondoufit-data.json`.
- **Vue de dessus** : deux axes en pointillés (gris = bassin fixe, bleu = épaules) montrent la rotation.
- **Phase d'effort (`eff`)** : dans `FAMILIES` (info.js), `eff: 1` signale que la 2e phase (`p[1]`) est l'effort (on descend d'abord : squat, pompes, dips, fentes, soulevé roumain, barre au front, roue abdominale). Elle commande la pastille « Expire / Inspire » (on expire à l'effort), le rythme (`tempoU(phase, loop, eff)` : l'effort est rapide, la descente lente) et la barre de position. Test : `anim.test.js` (« respiration »).
- **Outil de contrôle visuel** : `npm run dev` puis `/tools/anim-gallery.html?from=0&n=12&q=squat` affiche le début et la fin de chaque animation.

## Changer d'exercice depuis « Ajuster »`QuestFormModal` (mode édition) : section repliable « 🔄 Changer d'exercice » → `handleReplaceExercise` (`hooks/useQuestForm.js`) ne change que l'identité de l'exercice (`catalogId`, nom, icône, arène, `cardioMode`) ; historique, charge actuelle, objectif, séries / répétitions, aide, niveau et record restent. `isSwapCompatible` : même `type`, même `unit` et même caractère chronométré, donc pas de kg ↔ répétitions. `ExercisePicker` accepte `accept` (filtre) et `allowCustom={false}`. Test : `tests/ui/changer-exercice.test.js`.
## Charge (ou aide) changée entre deux séries
`lib/setLoads.js`. Séance guidée : `d.loads` / `d.assists` (une valeur par série) ; le réglage « Charge » / « Aide » s'applique aux séries pas encore faites (`setLoad` / `setAssist` dans `GuidedSession.jsx`). Historique : `entry.setLoads` / `entry.setAssists` (uniquement quand les valeurs diffèrent, séries réalisées) ; `entry.value` = charge la plus lourde et `entry.assistanceKg` = aide la plus faible (valeurs de record pour courbes, trophées, `quest.currentValue`). Tonnage / volume / 1RM estimé / calories utilisent la charge de chaque série. Coach (`computeExerciseTarget`) : si les charges diffèrent, la référence est celle de la DERNIÈRE série réalisée et on ne juge les répétitions que sur les séries faites à cette charge ou plus dures (séries manquantes comptées juste sous l'objectif → on garde la charge et on vise l'objectif) ; la règle de recul « 2 séances ratées » est ignorée dans ce cas. « Noter séance » (`hooks/useLogSession.js`, `modals/LogSessionModal.jsx`) propose la même chose : case « Charge (ou aide) différente selon la série » (impose la saisie série par série), `logSetOverrides[i]` = valeur propre à la série i, la valeur de base valant pour les autres ; les anciennes entrées gardent une charge unique.

## Mes maxima (onglet « 💯 Mes maxima »)
`lib/maxima.js` (pur, testé) : `estimateQuestMax(q, state, { useRpe, today })` → par exercice, selon `maxKind` : `load` (moyenne de 7 équations de 1RM : Epley, Brzycki, Lander, Lombardi, Mayhew, O'Conner, Wathen, séries de 1 à 15 reps, meilleure séance des 90 derniers jours, fourchette + fiabilité), `assisted` / `bodyweight` (charge soulevée = poids du corps × `bodyweightFactor` − aide ; aide ou lest estimés pour 1 rép), `timed` (meilleure tenue observée, pas de formule validée), `cardio` (Riegel, T2 = T1·(D2/D1)^1,06). Option « effort ressenti » : RPE → répétitions en réserve (max 3, Zourdos 2016), désactivée par défaut. Tableau % du 1RM ↔ reps (NSCA) dans `workingLoads`. Record réel saisi à la main : `gameState.maxRecords[questId]` (`kg` | `assistKg` | `extraKg` | `seconds` | `{distanceKm, minutes}` + `date`), il sert de référence pour les charges de travail (`components/MaxCard.jsx`, `tabs/MaximaTab.jsx`, sources citées dans l'onglet).

## Corriger une séance, décider contre le coach
- **Corriger** (onglet Journal, bouton « ✏️ Corriger » → `components/EntryEditor.jsx`) : `handleEditSessionEntry` (`hooks/useQuestActions.js`) reconstruit l'entrée avec `lib/history.js` (`rebuildEntry` : meilleure série, séries validées, calories, note automatique régénérée si elle n'avait pas été réécrite) puis remet l'exercice à jour (`questAfterHistoryChange` : valeur actuelle, aide, séries d'après la dernière séance, historique trié par date). Le coach se base sur l'historique, donc il repart des valeurs corrigées. L'EXP déjà gagnée n'est pas recalculée. Annulable (`registerUndo`).
- **Tu décides** (onglet Coach, sous chaque exercice) : `quest.coachOverride = { entries, load?, assist?, repsDelta? }`, posé par `adjustTarget` (`components/coach/CoachPanel.jsx`) et appliqué en fin de `computeExerciseTarget` (`change: 'manual'`, `manual`, `suggested` = proposition d'origine). Valable seulement tant que le nombre de séances de l'exercice n'a pas changé (`entries`) : dès qu'une nouvelle séance est enregistrée, le coach recalcule.

## Sauvegarde : fichier JSON dans un dépôt GitHub privé
- **Local** : `localStorage` clé `rondoudou_save_v1` (ne jamais la renommer : elle contient les données des appareils existants). **Photos souvenirs** : IndexedDB `rondoufit_photos` (`lib/photos.js`, avec un index `{id: updatedAt}` dans localStorage `rondoufit:photoIdx`), **synchronisées** avec GitHub par `sync/photoSync.js` : un fichier `photos/<id>.json` par photo (JPEG ~900 px en base64 + date, note) dans le dépôt de données ; envoi 3 s après un ajout/modification/suppression, reprise au retour sur l'app et toutes les minutes. Suppression propagée dans les deux sens ; un appareil neuf ne supprime jamais rien ; si les photos locales disparaissent d'un coup (navigateur vidé) on les retélécharge. Mémoire de synchro : `rondoufit:photoSync`. Les écritures venant de GitHub passent par `PhotoDB.put(p, { remote: true })` / `del(id, { remote: true })` (pas de renvoi). Export/import JSON toujours disponible dans l'onglet Souvenirs.
- **GitHub** (remplace Google Sheets depuis la refonte) : `sync/` + `hooks/useGithubSync.js`. L'utilisateur renseigne dans l'appli (pastille ☁️ de l'en-tête → fenêtre « Sauvegarde GitHub ») compte, dépôt privé, fichier (`rondoufit-data.json`) et un **jeton fine-grained** (Contents : lecture/écriture) gardé uniquement dans son navigateur (`rondoufit:github`). Même principe que l'appli Carnet EPS.
- **Algorithme** (`sync/engine.js`, testé dans `src/sync/sync.test.js`) : lecture du fichier → si seul GitHub a changé on le reprend ; si seul cet appareil a changé on l'envoie ; si les deux ont changé on **fusionne à 3 voies** (`sync/merge.js` : séances/pesées réunies par `id`, suppressions respectées, trophées réunis, `xp` = somme des gains, sinon la version la plus récente gagne). Envoi 2 s après une modification, reprise au retour sur l'app et toutes les minutes.
- **Sécurités (à ne jamais casser)** : on n'écrase jamais GitHub si le fichier est illisible/invalide ; un appareil neuf (jamais modifié : `rondoudou_local_ts` = 0) ne peut pas écraser une sauvegarde existante ; une modification faite pendant une synchro n'est pas perdue (compteur de version). Les changements automatiques (trophées débloqués) passent par `setGameStateAuto` : sur un appareil jamais utilisé ils ne comptent pas comme une modification.
- Marqueurs locaux : `rondoufit:sync` (sha + état commun), `rondoufit:dirty`, `rondoudou_local_ts`. Un champ `_savedAt` (ms) est écrit dans le fichier.
- **Modifier les données à la place de l'utilisateur** : cloner le dépôt de données privé, éditer `rondoufit-data.json` (mêmes champs que `gameState`, ids uniques), mettre `_savedAt` à l'heure actuelle en ms, committer et pousser. Les appareils reprennent le changement (ou le fusionnent s'ils ont aussi modifié).

## Pièges connus
- **localStorage partagé avec Carnet EPS** (même domaine `gab1point0.github.io`) : toujours préfixer les nouvelles clés par `rondoufit:`, ne jamais toucher aux clés `carnet-eps:`.
- **Tailwind compilé** : écrire les noms de classes en entier (`'bg-pink-500'`), jamais `` `bg-${couleur}-500` `` (la classe ne serait pas générée). Tailwind 3 (pas 4).
- L'application démarre **vide** (`INITIAL_STATE` : aucun exercice, aucune pesée) avec un écran d'accueil « Bienvenue ». Les tests d'interface démarrent par défaut avec des données de démonstration (`tests/ui/demo.js`, dates fixes du 21/10/2026) ; `launch({ empty: true })` donne une application neuve, et un test qui fournit sa propre sauvegarde ou une config GitHub n'a pas la démo.
- Ancienne version de l'appli (avant la refonte ergonomie du 28-29/10/2026) : tag et branche `sauvegarde-avant-refonte-ergonomie` sur GitHub (retour possible : voir l'historique git).
- Anciens objectifs conservés si on retire un exercice du catalogue (seul le catalogue change).
- Les hooks de `hooks/` reçoivent tout ce dont ils ont besoin en paramètre (pas de contexte global) : ajouter un paramètre plutôt qu'un import croisé.
